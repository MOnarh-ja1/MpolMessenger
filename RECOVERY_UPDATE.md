# Исправления восстановления связи

Это ограниченное обновление существующего клиента, не готовая версия Messenger 2.0.

## Исправлено

- Сбой сети/HTTP 5xx при запуске больше не удаляет сессию. Повторная попытка выполняется каждые 10 секунд и при событии восстановления сети. Ответ 401 аннулирует только ту сессию, с которой был отправлен запрос.
- После авторизации WebSocket обновляются список чатов, заявки и история открытого чата (последние 100 сообщений согласно существующему API). При возвращении в окно выполняется синхронизация.
- Запоздалые ответы истории и поиска не подменяют другой чат или более новый запрос. Ответ после выхода не восстанавливает сообщения в состоянии клиента.
- Событие заявки запрашивает заявки независимо от ошибок получения списка чатов и друзей.
- Повторный вызов подключения не создаёт второй открытый/подключающийся WebSocket.
- Docker-образ включает интерфейс, который открывает Windows launcher. Контекст сборки изменён с server/ на корень репозитория. Compose требует постоянную БД.

## Установка без изменения данных

Windows launcher для HTTPS открывает сайт указанного сервера. Поэтому сначала обновите серверный интерфейс `client/ui/`, затем перезапустите приложение. Замена одного EXE не обновит интерфейс удалённого сайта.

Перед обновлением сделайте резервную копию действующей БД и вложений. Схема БД этим обновлением не меняется; миграции не требуются. Не меняйте текущие адрес БД, конфигурацию сервера или Docker volumes.

Для существующего Compose-развёртывания, из прежнего каталога проекта и с прежним .env:

```sh
docker compose up -d --build api
```

Не используйте `docker compose down -v`: этот флаг удаляет тома. Если Docker собирается вне Compose, используйте `docker build -f server/Dockerfile .` из корня репозитория. Сервис должен иметь один процесс Uvicorn: существующая доставка WebSocket использует память процесса и не поддерживает несколько реплик без общего брокера.

## Проверка

```sh
node --check client/ui/app.js
node --test tests/test_client_recovery.cjs
python -m pip install -r server/requirements.txt httpx
python tests/test_friend_realtime.py
```

Проверено 10 сценариев JavaScript в Node с подставными DOM/сетью и серверный сценарий FastAPI с двумя аккаунтами на временной SQLite: доставка заявки, принятие, сообщение, сохранность сессии/дружбы/истории после закрытия соединений БД и повторного запуска lifespan приложения. Это не тест перезагрузки отдельного серверного процесса и не проверка удалённого PostgreSQL.

Windows x64 EXE собран кросс-компилятором Go; запуск на Windows и двух физических компьютерах не проверен. Workflow `Validate recovery fixes` повторяет тесты и сборку на Windows и сохраняет EXE в артефакте без публикации релиза.

Сервер в интернете этим изменением не обновлён. Звонки, запись голоса, новые аватары, новый дизайн, идемпотентная очередь отправки, полная офлайн-история и остальные функции 2.0 остаются отдельными задачами. Защищённое хранение сессии вместо localStorage также не реализовано.
