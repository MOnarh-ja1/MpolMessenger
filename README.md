## MPOL Messenger 2.9.0 — удаление чатов, профили, модерация

- **Всем пользователям:** кнопка корзины в открытом чате и «Удалить чат у себя» в меню «•••». Удаление скрывает чат и старые сообщения **только у вас**, не стирая историю другого участника. Новое сообщение снова покажет диалог с новой историей. «Избранное» защищено от удаления.
- **Профиль собеседника:** кнопка в шапке диалога, пункт в меню «•••», и кнопка «Профиль» в поиске по ID; доступны ник, аватар, описание, статус и обычная блокировка пользователя для себя.
- **Только разработчику:** в профиле открывается «Модерация» — временно забанить, разбанить или удалить аккаунт. Все операции проверяются **на сервере** по `MPOL_DEVELOPER_IDS` (ID из доверенного серверного списка). Обычный пользователь не может выполнить эти запросы даже через API. Нельзя банить или удалять свой аккаунт или другого разработчика.
- Бан сразу отзывает сессии и запрещает вход, но его можно снять. Для удаления аккаунта нужно ввести точный ID и подтвердить действие. Удаление очищает личные сведения, пароль, фото, вложения, собственные сообщения и активные сессии. **Технический обезличенный ID-заполнитель сохраняется в БД, чтобы не разрушать историю других людей**; восстановить удалённый аккаунт нельзя.
- Для управления разработчика должен быть **настроен** `MPOL_DEVELOPER_IDS` на сервере Render. Сами настройки репозитория не дают права модерировать живой сервер.
- Схема БД дополняется таблицами `chat_dismissals` и `account_moderation`, существующие аккаунты и чаты не обнуляются. Дополнительные тесты проверяют запрет доступа к чужим чатам и правам администратора.

## MPOL Messenger 2.8.0 — запоминание входа в браузере и на iPhone

- При входе в браузере MPOL по умолчанию включено **«Оставаться в аккаунте на этом устройстве»**. Токен сессии сохраняется между закрытиями вкладок Safari/Chrome и при повторном открытии PWA на iPhone; пароль не сохраняется.
- Важно: **EXE** по-прежнему использует отдельную сессию каждого окна, чтобы не смешивать аккаунты. В браузере можно снять галочку для входа только до закрытия вкладки.
- При временном отключении сети или перезапуске Render токен **не удаляется**. После восстановления связи есть кнопка «Повторить подключение» и автоматическая повторная проверка. При недействительном токене или явном выходе потребуется повторный вход.
- Срок действия серверной сессии — **30 дней**, затем вход потребуется повторить. В приватном режиме Safari и после очистки данных сайта сохранение не гарантируется. Safari и иконка «На экран Домой» могут иметь раздельные хранилища.
- Сохранение токена в браузере подходит для личных устройств; на общем компьютере лучше снять галочку. Выход из аккаунта удаляет токен из обоих видов браузерного хранилища.

## MPOL Messenger 2.7.0 — бесплатный резерв для звонков и HD-видео

- Когда собственный TURN не настроен, MPOL пробует **публичный Metered Open Relay** с опубликованным провайдером общим TURN-секретом. Список STUN/TURN выдаётся только вошедшим пользователям через `/api/calls/ice`. Пользователю не нужен VPS. Публичный TURN — внешний бесплатный сервис, а не инфраструктура MPOL: возможны ограничения, сбои и исчерпание квоты. [Источник и условия](https://www.metered.ca/tools/openrelay/). Провайдер указывает 20 ГБ бесплатного трафика в месяц. Мы не гарантируем этот лимит для каждого MPOL аккаунта.
- Видеосвязь использует целевое разрешение до 1280×720 и частоту до 30 FPS с битрейтным потолком до 2 Мбит/с вместо 400 Кбит/с. WebRTC снижает качество на слабой сети; даже обновлённая программа не гарантирует отсутствие задержек.
- Включено подавление эха и шума по умолчанию (опционально выключается при обрывах речи); локальное видео остаётся без звука, а звук собеседника воспроизводится один раз. Если два устройства физически рядом, лучше использовать наушники, иначе микрофон другого устройства может возвращать ваш голос.
- Для более устойчивой связи используйте собственный TURN через `MPOL_TURN_URLS`/`MPOL_TURN_SECRET`: он имеет приоритет над публичным. `MPOL_DISABLE_PUBLIC_TURN=1` отключает публичный fallback. Подробности: [FREE_CALLS.md](FREE_CALLS.md).
- **Без VPN:** клиент использует HTTPS/WSS и обычный WebRTC. Если ваш интернет-провайдер блокирует сам хост Render, обновление EXE не может снять сетевую блокировку; нужен доступный альтернативный адрес сервера или хостинг.

## Что находится в архиве

- `MpolMessenger.exe` — готовый Windows EXE (x64), **отдельный клиент**. При запуске открывает окно Edge/Chrome в режиме приложения. Браузер нужен установленный на ПК. Это **не нативное WPF-окно** и не полноценный установщик.
- `MpolMessenger.ico` — иконка MPOL, также встроена в EXE.
- `server/app.py` — сервер FastAPI / WebSocket, пользователи и сообщения.
- `server/start_server.bat` — локальный запуск сервера через Python.
- `server/requirements.txt` — Python-зависимости.
- `client/` — исходный код интерфейса и Go-лаунчера, `build_windows.bat`.
- `compose.yaml`, `server/Dockerfile`, `Caddyfile`, `.env.example` — вариант размещения сервера на VPS.

## Быстрый запуск на одном ПК (локальная проверка)

1. Установите **Python 3.11 или новее** с python.org (галочка *Add Python to PATH*).
2. Откройте `server/start_server.bat`, дождитесь сообщения `Uvicorn running on http://127.0.0.1:8000`. **Сервер должен оставаться запущенным.** При первом запуске потребуются интернет и установка Python-библиотек.
3. Дважды нажмите `MpolMessenger.exe`. По умолчанию новый клиент обращается к `https://mpol-messenger-api.onrender.com`. Для локального сервера откройте «Настроить» и укажите `http://127.0.0.1:8000`.
4. Создайте аккаунт: логин из латинских букв/цифр, пароль от 10 символов, никнейм.
5. Для проверки второго аккаунта используйте другой ПК, подключённый к *этому же серверу*, либо откройте отдельный профиль браузера. Другой ПК **не сможет подключиться к `127.0.0.1` на вашем ПК** — адрес localhost всегда указывает на устройство самого пользователя.

Примечание: пароли хешируются Argon2id; данные сохраняются в `server/mpol.db` в демонстрационном SQLite-режиме. Удаление этого файла стирает аккаунты и переписки. Резервные копии делайте при остановленном сервере.

## Реальное общение между разными ПК через интернет

Для этого разверните сервер на постоянно доступном VPS с доменом и HTTPS. В архиве есть пример **Docker Compose + PostgreSQL + Caddy**, который может автоматически получить HTTPS-сертификат, если домен направлен на VPS и порты 80/443 доступны.

1. Установите Docker + Docker Compose на VPS и укажите A/AAAA-запись домена на IP VPS.
2. Перенесите папку проекта на сервер. Скопируйте `.env.example` в `.env` и задайте настоящий `MPOL_DOMAIN`, `MPOL_DB_PASSWORD`, `MPOL_RECOVERY_SECRET`. Пароль БД используйте достаточно длинный, для примера Compose — только латиницу и цифры. Не публикуйте `.env` в GitHub.
3. В папке проекта выполните `docker compose up -d --build`.
4. Убедитесь, что `https://ВАШ-ДОМЕН/api/health` отвечает `{"ok":true,...}`.
5. На **каждом Windows-ПК** запустите `MpolMessenger.exe`, нажмите «Настроить» под формой входа, введите `https://ВАШ-ДОМЕН` и сохраните адрес. После этого пользователи могут регистрироваться и общаться независимо от своих устройств.

Клиент запрещает обычный HTTP для удалённых серверов; локальный `http://127.0.0.1` разрешён для тестов. Для публичного использования настройте защиту VPS, резервные копии PostgreSQL, журналы событий и SMTP.

## Что ещё не готово / ограничения

- **Публичный сервер запущен на Render**, аккаунты, сообщения и новые файлы хранятся в Neon PostgreSQL. Для эксплуатации без риска нужны резервные копии, SMTP, мониторинг, продвинутые ограничения и аудит безопасности.
- EXE открывает UI через Edge/Chrome в режиме приложения. Нативной полноэкранной рамки без стандартного заголовка Windows, системной трее, автозапуска, отдельного системного установщика и автоматических обновлений пока нет.
- Аватары пока представлены символами. Загрузка изображений аватара, продвинутые права групп, полноценное удаление групп, демонстрация статуса «прочитано» в группах и надёжное управление статусом доставки нуждаются в доработке.
- Уведомления — через браузерное API, требуют разрешения и открытого приложения. Фоновые push-уведомления при закрытом клиенте не реализованы.
- Сообщения **не имеют сквозного шифрования (E2EE)**; сервер может читать сохранённые сообщения. HTTPS защищает их при передаче.
- Ограничения запросов и WebSocket-соединения хранятся в памяти одного процесса. Масштабирование на несколько экземпляров требует Redis/pub-sub, внешнего хранилища файлов, дополнительных ограничений и аудита безопасности.
- Производительность/60 FPS в Windows 10/11 фактически не измерена на реальном ПК; EXE собран кросс-компилятором и **не запускался на Windows в этой среде**.

## Пересборка EXE

Для сборки нужен Go 1.23+ на Windows. Запустите `client/build_windows.bat`. Обновить иконку из `MpolMessenger.ico` можно через `python client/create_windows_resource.py` перед сборкой. Для разработки на Linux: `cd client && GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -ldflags "-H windowsgui" -o ../MpolMessenger.exe .`.
