# MPOL Messenger 3.1 — запуск в России без VPN

Результат: **один адрес HTTPS в доступном из России облаке** для браузера/iPhone, WebSocket-сообщений и API, плюс возможность выбрать этот же адрес в Windows EXE. Никакие аккаунты не переносятся автоматически.

> **Пока у MPOL нет опубликованного российского адреса.** Одного коммита в GitHub или установки нового EXE недостаточно: необходимо реально создать и запустить приложение на хостинге. Не публикуйте базу данных, пароли или токены в репозитории.

## Вариант без своего VPS — DADA Cloud (РФ)

DADA Cloud ([инструкция для GitHub](https://cloud.dada-tuda.ru/developer/applications-deploy-from-github)) указывает поддержку Docker/FastAPI, HTTPS и бесплатного первого приложения. Условия, доступность и поддержка WebSocket проверяются на созданном сервисе; платформа внешняя и не принадлежит MPOL.

1. Создайте свой аккаунт в DADA Cloud. Подключение к хостингу требует действия владельца аккаунта; ассистент не может создать сервис без него.
2. В Applications выберите **Deploy application → From GitHub**, затем репозиторий `MOnarh-ja1/MpolMessenger`, ветку `main`.
3. Выберите корень репозитория (Root directory `/`) и **Dockerfile** в корне. Образ запускает `server.app:app` и включает `client/ui`. Порт берётся из `PORT`, по умолчанию 8000.
4. В панели проекта установите защищённые переменные окружения:
   - `MPOL_DATABASE_URL` — **та же самая** PostgreSQL-база, что у действующего MPOL на Render, в синтаксисе `postgresql+psycopg://...`, с TLS/SSL; не создавайте пустую новую БД, если хотите сохранить аккаунты.
   - `MPOL_REQUIRE_PERSISTENT_DB=1` — не разрешать временную SQLite.
   - `MPOL_EPHEMERAL_STORAGE=0`.
   - `MPOL_DEVELOPER_IDS` — та же серверная разрешённая группа ID, если используется модерация.
   - Рекомендуется `MPOL_DISABLE_DOCS=1`. При необходимости добавьте настройки SMTP для восстановления паролей.
   - **Не размещайте реальные секреты в `.env`, GitHub, переписках или скриншотах.**
5. Запустите деплой. Откройте предоставленный хостингом адрес `https://<ваш-домен>`. Затем проверьте `https://<ваш-домен>/api/health`: нужно увидеть `"ok":true`, `"service":"mpol-messenger"`, `"durable_database":true`.
6. Войдите через HTML, проверьте существующий аккаунт, затем откройте второй аккаунт и отправьте сообщение через мобильный интернет. Убедитесь, что WebSocket (`wss://<ваш-домен>/ws`) действительно соединяется. **Запускайте один экземпляр сервера и один процесс**, пока MPOL не использует межсерверную доставку событий.
7. Установите Windows MPOL 3.1: в любом месте нажмите **Ctrl+Shift+S**, введите свой HTTPS-адрес, подтвердите его. Если старый Render недоступен, то же окно можно открыть на экране ошибки кнопкой «Сервер для России». MPOL проверит `/api/health` и не запишет неизвестный или незащищённый адрес.
8. На iPhone откройте **новый российский URL** в Safari и добавьте его на главный экран через «Поделиться» → «На экран Домой». Для нового происхождения сайта нужно войти заново; на сервере останутся прежние аккаунты, если строка PostgreSQL та же.

**Важно:** две копии MPOL на разных серверах (например, Россия и Render) пока не обмениваются событиями WebSocket между собой. Сообщения сохраняются в общей PostgreSQL, но звонки и мгновенные уведомления могут не доходить между подключившимися к *разным* серверам. Пока все собеседники должны пользоваться **одним и тем же** российским адресом. В будущем для многоузловой работы требуется Redis pub/sub или другой межсерверный сигналинг.

## Голосовые и видеозвонки из РФ

Приложение использует обычные HTTPS/WSS/WebRTC; **VPN не нужен при доступности всех служб**, но доступность основного сайта сама по себе **не гарантирует** прохождение аудио/видео через операторские NAT. Для сложных мобильных сетей нужен отдельный доступный STUN/TURN. В MPOL есть best-effort публичный Open Relay; его доступность в российских мобильных сетях не гарантируется. При необходимости нужен TURN-провайдер или сервер с подходящей связностью; можно использовать [пример coturn](relay/README.md).

## Как сохранить аккаунты

**Не переключайте `MPOL_DATABASE_URL` на новую пустую БД.** Два адреса сайта не означают две базы. Если доступ из РФ к Neon/PostgreSQL ограничен, необходима отдельная миграция базы с проверкой целостности и резервным копированием. В действующей архитектуре нельзя просто назначить новую базу без потери видимости аккаунтов.

При переносе персональных данных российских пользователей оцените применимое законодательство о локализации данных. Размещение только фронтенда в РФ при хранении PostgreSQL за рубежом само по себе не доказывает соблюдение этих требований.

## Для тестирования через Docker Compose

В репозитории есть `compose.yaml` + `Caddyfile` для собственного сервера. Конфигурация использует PostgreSQL, HTTPS и отдельный persistent volume для файлов. Команды из локальной папки, где хранится **только ваш** приватный `.env`:

```sh
docker compose up -d --build
```

Для общедоступного HTTPS потребуется домен с DNS и открытыми 80/443; это не заменяет развёртывание на российском хостинге.

## Безопасность

- Windows EXE принимает только HTTPS-адреса в форме `https://домен` — без учётных данных, путей, портов и IP-адресов. Выбор сервера проверяется по `/api/health` и требует отдельного подтверждения.
- Не подключайтесь к случайным сайтам, называющим себя «MPOL»: они могут запрашивать ваш пароль. Используйте только сервер, развёрнутый вами или доверенным администратором.
- Экран настроек работает локально в Electron без доступа к Node.js из удалённой веб-страницы.
- Старая ссылка `onrender.com` остаётся вариантом восстановления в EXE. MPOL не обещает доступность любого адреса у всех операторов связи.
