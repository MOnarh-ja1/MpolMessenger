# MPOL Messenger 2.2.0 — Исправления

## Сообщения и аккаунты

- Токен входа сохраняется в `sessionStorage` конкретного окна вместо общего `localStorage`. Это устраняет эффект, когда вход в другой аккаунт во втором EXE меняет аккаунт первого окна.
- В левой панели показан **текущий аккаунт** (ник + ID). Сообщения оформлены по реальному `user_id` отправителя относительно `/api/me`: свои справа, сообщения остальных слева.
- На чужих сообщениях отсутствует кнопка удаления; сервер также отвечает HTTP 403 на попытку удалить чужое сообщение.
- У входящих сообщений отображается ник отправителя и в личных чатах, и в группах.
- При первой загрузке новой версии прежний `localStorage`-токен переносится в текущую вкладку. После этого каждое новое окно может потребовать вход в свой аккаунт. Это сделано для исключения смешивания двух аккаунтов.

## Интерфейс

- Высота окна вычисляется по динамической области просмотра; исправлено ограничение `body{min-width:690px}`, из-за которого обрезался интерфейс на узких окнах.
- Блок сообщений является прокручиваемым и не выталкивает строку ввода вниз.
- Корневая страница больше не масштабируется свойством `zoom`, которое могло обрезать нижнюю часть после F11. Масштабирование текста остается доступно.
- В CI добавлена проверка реального рендеринга в Edge/Chrome для нескольких размеров окна.

## Звонки

- Для всех дорожек входящего звонка используется один постоянный `MediaStream`: при добавлении видео больше не пересоздаётся аудиопоток.
- Звук всегда воспроизводится одним `<audio>` элементом; видео отключено от звукового выхода, чтобы исключить двойное воспроизведение.
- Для начала звонка используется менее агрессивная обработка микрофона: эхоподавление включено, шумоподавление по выбору (изначально выключено), автоматическая регулировка усиления выключена. В разных браузерах эти ограничения могут поддерживаться по-разному.
- Видеозвонки используют меньшую частоту кадров/битрейт, чтобы освободить канал для речи.
- В окне звонка отображаются приблизительные потери аудиопакетов и состояние соединения. При обрыве предусмотрена сигнализация переподключения ICE.

## Известные ограничения

- TURN-сервер **не подключён**; на некоторых сетях за NAT/брандмауэром звонки не устанавливаются либо остаются нестабильными, даже после этих исправлений.
- Сетевые условия, устройства и драйверы собеседников не могут быть полностью проверены автоматически. Нужен реальный тест двух компьютеров.
- У приложения нет сквозного шифрования; HTTPS/WSS защищают соединения с сервером.
- Данные аккаунтов, переписок и вложений остаются в существующей Neon PostgreSQL базе. Миграция или удаление пользователей не выполняются.

Последний запуск GitHub CI должен подтвердить тесты фронтенда, двух окон, сигнализации звонков, а также сборку Windows EXE перед выпуском.
